# ASCAutoPayroll

A Selenium-powered automation tool for UMBC student timesheet entry. It scrapes attendance/visit records from the TRAC Cloud system, parses and rounds the raw clock-in/clock-out times into billable increments, and then auto-fills the resulting entries into the UMBC PeopleSoft (PSHR) timesheet portal — removing the need to manually transcribe hours every pay period.

## How it works

The tool runs as an interactive CLI with four actions:

1. **Process a Timesheet** — walks through the full pipeline below and enters the rows into PeopleSoft.
2. **Process from a schedule CSV** — skips TRAC scraping and parsing; enters the times from a weekly schedule CSV instead (see below).
3. **Dry run** — runs the pipeline up to the CSV export and pay estimate, then stops (never touches PeopleSoft).
4. **Exit** — closes the browser and quits.

### Schedule CSV mode

If you work fixed hours, list your weekly shifts in a CSV (see `example.csv`):

```csv
day,start,stop
mon,11:00,13:00
tue,11:00,14:00
tue,16:00,18:00
```

After you pick a pay period, each row is applied to every matching weekday in that period, and the times are entered exactly as written (no rounding). A day can have several rows.

To give the two weeks of a pay period different hours, add an optional `week` column (`1` = first week of the period, `2` = second). A blank week means the row applies to both weeks. If only one week number is used, or the column is absent, that week is repeated for both:

```csv
day,start,stop,week
mon,11:00,13:00,1
mon,14:00,16:00,2
fri,09:00,10:00,
``` Days accept `mon`..`sun` or full names; times accept `14:00` or `2:00PM`. Pass `--schedule path/to/file.csv` to pre-fill the path prompt; `--dry-run` works here too.

### Pipeline

1. **Select a pay period** — `prompt_for_timeblock()` reads the generated pay-period list and presents a fuzzy-searchable menu, defaulting the cursor to the period containing today. Periods are two-week blocks generated by `TimeBlockGenerator` and are auto-regenerated on startup so the list never goes stale.
2. **Scrape attendance data** — `UMBCTimesheetScraper` opens TRAC Cloud (logging in only if the persistent session has expired), waits for you to confirm the page has loaded, and saves the rendered HTML listing to disk (`Attendance Listing.html`).
3. **Parse and round times** — `AttendanceParser` extracts visit rows from the saved HTML with BeautifulSoup, rounds start times to the nearest hour and end times to the nearest 15 minutes, computes billed hours/duration, and exports a per-period CSV along with an estimated gross/net pay summary.
4. **Auto-fill the timesheet** — after you confirm the parsed rows, `TimesheetAutomator` logs into the UMBC PeopleSoft timesheet page, switches into the correct iframe, types each parsed row (date, start, end, break) into the web form, then reads the fields back and prints a per-row ✓/✗ verification before you submit.

├── run.sh                  # uv sync + run helper
├── pyproject.toml          # Project metadata & dependencies
├── src/autopayroll/
│   ├── interface.py        # CLI menu loop, orchestration, lazy WebDriver (Interface)
│   ├── config.py           # Settings, credentials, URLs, tunables (ConfigSettings)
│   ├── timeblocks.py       # Pay-period generation + selection prompt (TimeBlockGenerator)
│   ├── scraper.py          # Scrapes TRAC Cloud attendance page (UMBCTimesheetScraper)
│   ├── parser.py           # Parses/rounds attendance HTML into a billing CSV (AttendanceParser)

│   ├── automator.py        # Fills the PeopleSoft timesheet form (TimesheetAutomator)

└── tests/                  # pytest unit tests for the pure parsing/rounding/period logic
```

## Requirements

- Python >= 3.13
- [uv](https://docs.astral.sh/uv/) for dependency management
- Firefox (automation uses `selenium`'s Firefox WebDriver via a dedicated profile)

Runtime dependencies (see `pyproject.toml`): `selenium`, `pandas`, `beautifulsoup4`, `lxml`, `questionary`, `python-dotenv`, `keyring`. Dev tools (`pytest`, `ruff`, `pyinstaller`) live in the `dev` dependency group.

## Quick install (one-click)

The installer bootstraps everything — it installs `uv` if needed, sets up the
app, and creates a launcher you can double-click. You only need Firefox
installed separately.

| OS | Do this |
|----|---------|
| **Windows** | Double-click **`install.bat`** |
| **macOS** | Double-click **`install.command`** in Finder |
| **Linux** | Run **`./install.sh`** in a terminal |

After it finishes, launch the app by:

- **Windows** — double-click `AutoPayroll.bat` (or the new Desktop shortcut)
- **macOS** — double-click `AutoPayroll.command`
- **Linux** — run `./AutoPayroll.sh` (or find *ASCAutoPayroll* in your app menu)

> First-run note: macOS may warn that `install.command` is from an
> unidentified developer — right-click it and choose **Open** the first time.
> On Windows, if SmartScreen prompts, choose **More info → Run anyway**.

## Manual setup

1. Install dependencies and run:
   ```bash
   ./run.sh
   ```
   which is equivalent to:
   ```bash
   uv sync
   uv run autopayroll
   ```

2. On first launch, `ConfigSettings` creates a config directory at `~/.config/autopayroll/` containing:
   - `settings.env` — credentials and the Firefox profile path (created with `600` permissions)
   - `timeblock.env` — auto-generated, auto-refreshed list of pay periods
   - `data/` — where scraped HTML and per-period CSV exports are saved

3. Fill in `~/.config/autopayroll/settings.env`:
   ```env
   PROFILE_DIR=""     # Path to a Firefox profile (used for persistent login/session state)
   UMBC_USR=""        # UMBC username
   UMBC_PAS=""        # UMBC password (optional — see Credentials below)
   ```
   At minimum `PROFILE_DIR` and `UMBC_USR` should be set. The password may be left blank.

### Credentials

The password is resolved in this order:

1. `UMBC_PAS` in `settings.env`, if set.
2. The system keyring (service `autopayroll`), if a password was saved there previously.
3. An interactive prompt — with the option to save it to the keyring so it isn't asked again.

Leaving `UMBC_PAS` blank and using the keyring/prompt keeps your password out of the plaintext settings file.

## Usage

```bash
uv run autopayroll            # interactive menu
uv run autopayroll --dry-run  # default the menu to parse-only
uv run autopayroll --schedule example.csv  # pre-fill the schedule CSV path
uv run autopayroll -v         # debug logging
```

Then follow the interactive prompts:

1. Choose **Process a Timesheet** (or **Dry run**).
2. Select a pay period from the fuzzy-search list (today's period is pre-selected).
3. Let the browser open TRAC Cloud and load your attendance listing; confirm with **Yes** once the page has fully loaded.
4. The tool parses the listing, prints a summary of billed hours and estimated pay, saves a CSV, and shows the parsed rows.
5. Confirm to continue; the browser navigates to PeopleSoft and auto-fills each row. Review the ✓/✗ verification, then press Enter to close the browser once you've submitted.

## Development

```bash
uv sync                 # install runtime + dev dependencies
uv run pytest           # run the unit tests
uv run ruff check src   # lint
uv run ruff format src  # format
```

The unit tests cover the pure logic that determines pay (time rounding, duration math, date filtering, pay-period generation) against a checked-in HTML fixture in `tests/fixtures/`. The Selenium flows are not automated — they depend on live UMBC auth and Duo — so use the manual smoke test below after changing `scraper.py` or `automator.py`.

### Manual smoke-test checklist

1. `uv run autopayroll --dry-run` and pick the current pay period.
2. Confirm the browser opens TRAC and (if the session is fresh) logs in without prompting.
3. Confirm the printed billed-hours/pay summary and the CSV under `~/.config/autopayroll/data/` look right.
4. Re-run without `--dry-run`; confirm the parsed rows preview, then that each row is typed into PeopleSoft.
5. Check the ✓/✗ verification output matches the CSV before submitting.

## Notes

- Tunables live in `ConfigSettings`: `pay_rate` (default `17.5`), `wait_time`, `short_wait_time`, and the two portal URLs. Change them there rather than in the pipeline code.
- The Firefox profile directory is reused across runs to help preserve login/session cookies (e.g., Duo two-factor state), reducing repeated 2FA prompts. When the session is still valid the login form is skipped automatically.
- Generated artifacts (pay-period list, scraped HTML, per-period CSVs) are written under the user config directory, not the project directory, so re-running the tool won't clutter the repo.
